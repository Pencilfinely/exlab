# ExLab 0.6.4 · 修复旧镜像仓库阻塞迁移

- 修复一直显示 **等待结束：expman-registry**。这是旧版节点安装器创建的常驻镜像仓库，不会自行结束；现在能核验并接管，无需手动停止或删除。
- 当前实验运行期间仓库继续服务，实验与结果回传完成后再停止仓库、迁移数据。保留原有 `localhost:5000` 地址、镜像摘要和仓库卷；失败恢复时重新启动原仓库。
- 补齐 5000 端口的本地镜像识别。新安装的仓库增加明确归属标记，旧的无标签仓库按原安装器的镜像、挂载、环境和本机端口核验。
- 同名但配置不同的容器不会被接管；其他容器占用仓库卷时仍等待其结束。
- 检测到 Ubuntu 内另有原生 Docker 默认网桥时提前保留原环境；独立引擎启动前也会检查，避免影响其他引擎的网络。

**已经卡在 0.6.3 的迁移队列：** 在迁移窗口点击取消，等恢复完成后更新至 0.6.4，再点击“排队迁移并开启”。关闭窗口只是收进托盘，不会取消旧队列；正在运行的旧进程也不会自动换成新代码。

回归覆盖旧仓库识别、实验排队、停止前身份复核、取消与恢复，以及两种 Docker 镜像存储下的真实仓库数据传输、原摘要拉取和回滚。未代为修改远程服务器。
