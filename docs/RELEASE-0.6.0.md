# ExLab 0.6.0 · 生活质量更新

围绕磁盘、运行环境和后台开销重整 Worker 的资源生命周期。

## 存储与环境

- 新增 **Worker → 设置 → 存储与环境**：扫描占用、清理可回收项、查看保留原因。
- 结果、权重、续训数据保留。成功实验的代码先按版本归档；重复权重在两份哈希一致后删除工作副本；回收已结束的只读容器。
- 旧环境镜像只在没有当前配置、模板、待续训任务或其他容器引用，且原摘要能从仓库恢复时清理。共享镜像与无法证明归属的内容保留。
- 自动清理默认开启，每六小时检查一次，只在本节点没有活动任务时启动；维护线程降低 CPU 和 I/O 优先级。可关闭或取消。
- Windows 提供旧版迁移归档清理及独立 Worker 虚拟磁盘回收，显示 Windows 实际可用空间变化。清理文件与回收虚拟磁盘分开计量，不把逻辑删除当作磁盘已经缩小。

## 迁移与恢复

- 无需复制整套 Ubuntu。实验数据原位保留，独立引擎使用单独的程序、配置、服务与存储；镜像和仓库直接流式转移，不生成完整中间 tar。
- 逐项核验镜像和仓库内容，完成 CUDA 与节点身份验证后再清理原引擎中可回收的 ExLab 副本。交接前可恢复原配置，交接中断可继续完成。
- 不相关的 Desktop 工作保留。迁移仍需要镜像缓存的临时空间，具体以检测结果为准。

## 性能与交互

- 历史结果发现改为有索引的有界扫描，活动实验优先；减少重复硬件探测、全量结果解析与无变化的数据库写入。
- 空闲回传控制降低轮询频率；后台浏览器页面停止轮询，前台仅重建当前页面，回到页面立即刷新。
- 新运行容器的 Docker 日志使用轮转，单容器上限约 30 MB；独立引擎启用构建缓存回收。实验自己写出的结果、权重与日志文件不受 Docker 日志轮转影响。
- 不改变训练参数、精度、随机种子、任务资源预算或结果协议；启动任务前仍重新探测资源。

2 万条历史实验加 1 条活动实验的本机基准：单次发现由 20,001 条 / 458 ms 降至 1 条 / 0.07 ms；该步骤 Python 分配峰值由约 90 MB 降至约 5 KB。这是扫描环节的测量，并非整机或训练性能承诺。可运行 `python -m scripts.benchmark_qol` 复测。

部署后仍须在目标服务器完成实际 GPU 迁移和未登录重启验收。CPU 集成测试与空 VHDX 测试不能代替远程 2080 Ti 的硬件验收。
