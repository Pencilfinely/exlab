# 存储与环境

打开 **Worker → 设置 → 存储与环境 → 扫描空间**，再点击 **清理可回收项**。清理按当前状态重新检查，每项成功后立即释放对应副本；可在项目之间取消。详情列出保留原因。

| 内容 | 处理方式 |
|---|---|
| 结果、唯一权重、待续训或未回传数据 | 保留 |
| 成功实验的重复权重 | 两份哈希一致且档案可用后，删除输出目录中的重复副本；`archived-files.json` 记录档案位置 |
| 成功实验的干净代码工作副本 | 先写入按内容去重的 `code_archive`，记录版本、环境摘要和参数，再让 Git 删除工作副本 |
| 有改动、忽略文件、子模块、内容过滤器或特殊归档规则的代码目录 | 保留，避免遗漏本地文件 |
| 成功实验的已退出只读容器 | 归属和状态核验后删除；训练输出在挂载目录中保留 |
| 过期环境缓存 | 当前配置、模板、可恢复任务和任何容器均未引用，并确认原镜像摘要仍可从仓库恢复后才清理 |
| 共享镜像、外部容器、未知文件、镜像仓库 | 常规清理保留；不运行全局 Docker prune |

自动清理默认开启，启动五分钟后首次检查，之后每六小时检查；有活动任务时延后。维护线程使用较低 CPU / I/O 优先级。可以关闭自动清理；手动扫描不会暂停接单，执行清理时会暂缓准备和接收新的运行代次。

## 把空间还给 Windows

一键迁移现在可选择实际 **Worker 数据位置**。例如改为 `E:\ExLabWorker\Ubuntu-Data`，Ubuntu 虚拟磁盘、内部实验数据和新独立引擎都随之落在 E 盘。先点 **检测空间**；跨盘所需空间包含现有 VHDX 文件和新环境余量，150 GB 可用空间不保证适合所有节点。移动成功后释放原位置的 VHDX 文件，不产生 C 盘中转 tar。详见 [改盘条件与恢复](UNATTENDED-WORKER.zh-CN.md)。

Linux 文件系统释放的空间不一定立即成为 Windows 可用空间。独立 Worker 先在主界面 **停用并释放**，再打开存储窗口点击 **回收磁盘空间**。程序仅处理已登记、已停止、专供 Worker 的 Ubuntu：整理空闲块，退出该发行版，再调用 Windows 虚拟磁盘压缩 API。需要管理员权限；完成后算力保持停用。结果按 Windows 可用空间的实际变化显示，可能是 0。

**清理迁移备份**用于已完成的旧版整套复制迁移。只删除当前迁移记录中经过哈希核验的导出 tar，保留配置、校验记录与实际运行的虚拟磁盘。原 Ubuntu 不会被自动注销。

Docker Desktop 若仍承担其他工作，其虚拟磁盘不会被强行关闭或压缩。原位迁移成功后会尝试回收已校验的 ExLab 原引擎副本；共享或发生变化的对象保留。该部分在 Desktop 磁盘中的物理空间回收，仍取决于 Desktop 的磁盘维护。不能把扫描显示的逻辑大小直接相加，当成最终可腾出的 Windows 空间。

## 复现和查找

实验数据库保留任务原始说明；每个归档的代码工作副本在 `runs/<任务 ID>/code-archive.json` 中记录提交、参数、环境和代码归档路径。权重从实验档案按需下载，输出目录中的 `archived-files.json` 也能定位保留副本。清理不承诺远程仓库永远在线，因此当前配置、待续训与无法验证恢复条件的镜像会留在本机。

磁盘 API 的行为依据 [Microsoft 虚拟磁盘压缩说明](https://learn.microsoft.com/en-us/windows/win32/api/virtdisk/nf-virtdisk-compactvirtualdisk)；Docker 的共享层与卷回收规则见 [Docker 清理说明](https://docs.docker.com/engine/manage-resources/pruning/)。
