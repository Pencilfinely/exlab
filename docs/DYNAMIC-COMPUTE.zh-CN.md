# 动态算力、执行状态与跨节点接手

这套机制适用于常开服务器、可能夜间断电的实验室机器、个人台式机和需要携带的笔记本。节点在线状态、是否允许使用、资源容量分别记录。失联不会自动触发另一份训练。

## 两类回传

**执行状态**用于规划、调度和续训。心跳报告中的 `execution_state` 携带执行代次、训练进度、是否已启动、是否确认停止、释放原因和检查点清单；已有运行观测、计时与资源快照继续走执行同步。状态可更新、按序接受，旧报告不能覆盖新状态。单条扩展状态上限 128 KiB，心跳按整个请求预算分批发送。

**最终结果**继续使用现有轻量 `experiment-results-v1` 协议：每个实验/尝试的一份不可变结果 JSON、指标和必要的来源/证据引用。64 KiB 是建议大小，1 MiB 是传输硬限制。执行状态、续训文件和模型字节不会追加到结果 JSON。历史结果回传、独立验收和证据按需提取继续保留。

续训文件由独立后台线程扫描、冻结并传输，与心跳和最终结果发送分开。检查点以 SHA-256 校验，512 KiB 分块，丢失确认或重连后查询接收端偏移继续发送。中心完整接收并校验后才出具备份记录。模型仅在节点上保存，或者仅有结果送达，都不表示已经具备跨节点恢复能力。

## 节点可用策略

在「算力」的节点卡片点击「可用策略 / 维护」：

- 节点类型可选常开、个人主机、便携设备，用于记录使用性质，不会根据名字猜测硬件能力。
- **允许接单**：仍须满足原有运行时段、资源预算、本地授权和节点接单模式。
三档操作分别记录执行意图和 Worker 的实际核验结果：

| 操作 | 接单 | 现有实验 | 本机任务与环境 |
|---|---|---|---|
| 暂停接单（`drain`） | 暂停 | 继续运行、继续占用资源 | 保留 |
| 停止实验并暂停接单（`stop`） | 暂停 | 请求保存，确认停止 | 保留任务归属及容器环境，等待显式续训 |
| 停止实验、暂停接单并释放训练资源（`release`） | 暂停 | 请求保存，确认停止 | 归还可交接任务，清理已停止且归属已核实的实验容器，确认训练进程退出 |

“已请求”“正在保存并停止”“正在释放”“已释放”和“执行未完成”分别显示。策略版本确认只代表 Worker 接收了策略。`compute_control` 是独立的执行回执，绑定当时实际生效的本地/Center 策略；切换策略或到期后，旧回执不能证明新操作完成。离线只显示上次回报，不能视为已经释放。

新版 `compute-control-v2` Worker 才能使用独立的停止档位、核验容器清理并回传资源释放结果。旧版 Worker 的释放策略继续兼容，但不能据此显示“已释放”；界面会要求升级。自动托管也必须读取匹配的执行回执，持续的核验失败会进入规则巡检。

- 可填写结束时间；留空表示手动恢复。定时策略到期仍须满足其他限制。
- 笔记本可设置仅插电时提供算力。供电状态未知时暂停，WSL 从 Windows 宿主机查询电源，原生 Linux 从电源设备查询。
- 维护时间使用明确的开始/结束时刻。每日风险时段使用 Worker 本地时间，如 `22:00-08:00`；风险是调度估计，不代表已测量的断电概率。

可以按以下方式配置这四台设备，再根据实际观察调整风险和预计耗时：

| 节点 | 类型 | 主要策略 |
|---|---|---|
| A6000 | 常开节点 | 平时可用，假期维护前添加维护时间 |
| 2080 Ti | 常开节点 | 夜间增加中断风险，可续训任务更适合放在此时运行 |
| 5070 ROG | 便携设备 | 仅插电提供算力，外出前主动释放 |
| 5070 Ti | 个人主机 | 平时可用，游戏或关机前临时释放 |

「游戏 · 释放训练资源」打开预填两小时的策略表单，提交前可以修改时长和限制。它释放本实验台训练进程的 GPU、CPU 和内存占用；控制代理、共享 Docker/WSL、项目文件及检查点保留。完整退出虚拟机并释放 WSL 内存使用 Windows Worker 的「停用并释放 Docker / WSL」，界面会分别报告 Docker、其他会话与 WSL 的关闭情况。定时策略不会关闭共享运行环境。超过 Worker 已配置的停止宽限时间后会结束自身训练进程，无完整续训能力的任务需要重新提交。

本地限制在 Center 暂时离线时仍然生效。Worker 所在的 Python/WSL 环境支持：

```text
python -m expman.worker_service compute-policy --compute-mode drain
python -m expman.worker_service compute-policy --compute-mode stop
python -m expman.worker_service compute-policy --compute-mode release --minutes 120
python -m expman.worker_service compute-policy --compute-mode available
python -m expman.worker_service compute-policy --require-ac
```

这些命令写入所选节点配置旁的 `compute-override.json`，由在线代理执行，不重启代理。保存回执不代表停止/释放完成，可用 `python -m expman.worker_service status` 查看 `compute_control`。解除本地限制后，Center 保存的限制继续生效。恢复接单不会自动续训已手动停止的实验。

## 队列、预计工作量和反馈

单次实验、任务模板和矩阵的算力分配表单中，可以填写预计运行分钟数、期望完成时间和是否允许迁移。它们保存在 `planning`，不改变算法参数。

自动分配同时考虑候选/偏好限制、环境与数据兼容性、节点预取容量、预计剩余工作量、中断风险以及下一次维护。已完成且计时完整、没有跨节点交接的同类实验，会按节点保存最近最多十次样本的中位耗时估计。同类判断包括代码/项目版本、资源预算及除 seed 外的参数。没有记录时使用填写的预计时长和原有速度配置，未填写时使用启发式默认值；不声称是准确完成时间。不可续训且预计跨越维护开始的任务等待其他节点。

未分配任务优先按有效优先级排序，等待每小时增加一级排序权重，最多增加二十级；同等权重再考虑期望完成时间和提交时间。截止时间是排序依据，不保证按时完成。

在未分配实验详情中，可以调整优先级或勾选「暂缓分配」。此控制独立于不可变的实验配置，版本冲突会拒绝更新。已被节点领取的任务须通过停止或交接处理，避免在启动边界直接收回归属。

## 交接与恢复

实验详情将「执行状态与续训」和结果回传分别显示。点击「保存并交接」，可指定其他节点，也可自动选择其他兼容节点。节点释放策略也能触发自动交接。

交接必须满足：

1. 原 Worker 报告确认进程已经退出。只有失联、代理重启或容器情况不明，不满足条件。
2. 已启动的实验必须声明真实续训能力，并具有对应的完整、已在中心校验的检查点。尚未启动的任务无需伪造检查点。
3. 目标 Worker 支持新协议、部署了兼容项目，且满足原任务的候选节点/GPU限制与可用策略。

满足条件后保持同一实验 ID，为新的执行分配更高代次和尝试编号；目标 Worker 下载并校验检查点，完成代码/环境准备后才启动。累计运行时长跨节点接续。旧代次的报告不会改变当前任务，历史尝试的轻量结果和证据仍归原节点，允许迟到回传。

手动指定节点、限定 GPU 或关闭迁移的实验不会绕过限制。无续训入口、无检查点或没有目标容量时会显示等待状态，不偷偷从头重跑。原节点恢复可用后，自动释放的任务也可以由该节点重新接手；已手动停止的其他任务不会因此自动恢复。

手动停止会取消正在等待的自动交接。关闭迁移的实验在释放后需在原节点手动恢复。失联但尚未确认停止的任务继续保留原归属；当前版本没有租约看门狗，因此不会在无法排除原进程仍运行时强行接手。

现有轻量结果任务可使用交接；旧版完整归档任务保持原节点归属。建议为后续实验使用默认轻量协议。检查点目前保留在节点缓存和中心独立目录，并纳入多 Center 的完整同步；没有自动清理历史检查点的策略，需要预留存储空间。突然断电只能恢复到最后完整备份的检查点。

## 可选 AI 规划

「算力」页面提供「AI 规划建议」，沿用设置中的兼容服务，默认关闭。只有点击生成时才发送要求、节点策略/显卡摘要和最多一百个未分配任务的资源与规划摘要，不发送源码、数据集、训练日志或完整参数。

AI 只返回节点策略修改和队列优先级建议。后端校验字段、范围与已知身份，显示当前值和建议值，由用户逐项应用；应用仍执行正常的版本校验。AI 不签发执行许可，不修改科学参数、续训能力或结果格式。AI 失败不影响规则调度。

## 协议与验证

新增能力：`dynamic-compute-v1`、`execution-state-v1`。新节点和旧节点可共存，新的可用策略和交接要求升级相应 Worker。

管理员接口：`POST /api/compute-policy`、`/api/execution/handoff`、`/api/planning/queue`、`/api/planning/assist`。节点专用接口：`POST /api/execution/checkpoints`、`/api/execution/checkpoints/download`。下载只能读取分配给当前执行代次的检查点；上传不能推进已失效的执行代次。已完成上传可幂等重取回执。

自动验证包含策略与版本冲突、插电限制、断点传输与错误哈希、执行状态/结果隔离、失联不重复派发、旧代次隔离，以及通过真实 HTTP 和两个真实 CPU 演示子进程完成跨节点续跑。GPU、宿主机电源切换、实际游戏占用和真实算法恢复仍需在对应设备验收，演示测试不代表这些硬件验收已经完成。

## 自动托管与各端接入

手动 AI 预览之外，现已支持开启自动化介入，由 Center 在后台按状态变化规划、执行和核验，无需逐条点击。规则默认每 10 秒巡检，AI 默认至少间隔 15 分钟、活跃任务每小时复查，每小时最多 4 轮；两条循环独立，模型预算用完或响应缓慢时规则继续检查。AI 可编写受限 JSON 规则交由本地循环消费，报告使用分页和按需弹窗。Windows 本地可用时间窗口、Linux CLI 和 Monitor 使用相同的执行协议；外部 GPT/Codex 可通过 MCP/HTTP 查询、控制或委托系统 AI。详见 [AI 自动托管与外部 agent 接入](AI-AGENT.zh-CN.md)。
