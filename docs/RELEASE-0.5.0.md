# ExLab 0.5.0

实验台统一命名为 **ExLab**：主控 **ExLab Center**、算力端 **ExLab Worker**、手机端 **ExLab Monitor**。GitHub 仓库为 `Pencilfinely/exlab`，安装包和 ZIP 统一使用 `ExLab-0.5.0-…` 前缀。Python 包名 `expman`、原数据目录和连接身份继续兼容旧版。Windows 保留旧 EXE 入口作为升级兼容别名。

## Docker 与停用

- Windows Worker 启用算力前检查所选 Ubuntu 的本机 Linux Docker socket。Docker 未就绪时可同意启动 Docker Desktop，客户端等待连接后继续准备。登录后台启动遇到 Docker 未就绪会显示状态窗口，等待你主动启用。
- 修复保存的 Docker socket 在 Desktop / WSL 重启后失效导致准备持续失败的问题。代理执行命令和归档日志使用同一 Docker endpoint。
- 两端桌面窗口和托盘提供“停用并释放资源”，软件窗口和连接身份保留。Worker 先请求实验保存并停止；没有原生续训能力的实验记录为中断。恢复算力不会自动重新运行这些实验，需要在实验列表明确恢复。
- 退出使用同样的保存流程。停止受管理实验后停止 ExLab 镜像仓库；Docker 中无其他运行容器且没有其他代理时，使用 Docker Desktop 的 stop 命令；Ubuntu 无其他用户进程时终止此发行版，其他发行版也空闲时才关闭整个 WSL VM。镜像、数据、检查点和待回传文件保留。
- 停用后的状态刷新不再执行 WSL 命令，避免每五秒重新唤醒环境。原生 Ubuntu 只释放 ExLab 镜像仓库；不擅自停止系统 Docker 服务。
- Center 本身不需要 Docker / WSL，停用会关闭管理服务和它打开的页面，不停止远端计算。仍在使用资源的 Worker 要在自己的客户端停用。

## 两台 Center 使用同一工作空间

1. 在 5070 Ti 的 **设置 → 连接另一台 Center** 填 ROG 名称和 5070 Ti 的可访问地址，创建并复制 Center 凭证。
2. 在 ROG 安装同版 Center，使用空数据目录，在 **设置 → 接入已有工作空间** 粘贴凭证，并填算力端能够访问的 ROG 地址。
3. ROG 立即同步项目、实验、实验矩阵、节点凭证、移动设备权限和已完整回传的结果。之后每 30 秒自动同步，支持中断后续传。数据库和文件均校验后才提交副本；本机管理员凭证独立保留。
4. 平时从 ROG 操作，请求由 5070 Ti 执行。5070 Ti 临时离线时，可查看上次同步的实验、矩阵和结果；修改需要恢复连接。
5. 需要独立外出时，在原主控仍在线时点击 ROG 的 **由本机接管调度**。原主控先持久化冻结，然后完整同步，ROG 才接受调度。请等同步和交接成功再关掉 5070 Ti。已连接新版 Worker 会学习备用主控地址，不会重复创建已有实验。
6. 原 5070 Ti 在确认 ROG 接管后自动转为同步主控，重开时会继续同步，返回后再次交接即可换回。为从未连到过备用地址的离线 Worker，重新导出同一节点的配对文件 / 连接凭证，保留原节点身份。

交接必须能够联系原主控，离线副本不能强行接管，以免形成两个调度主控。两端必须使用相同版本。数据库同步上限为 64 MiB；每个项目 / 文件上限 32 GiB。仅在局域网或已有可信私网使用；此版本不会替用户建立公网网络或提供云账号服务。

Center 凭证允许整个工作空间的数据访问与常规操作，可在调度主控撤销。它不会提供原主控的管理员令牌或本地目录访问权限。项目文件夹导入在当前调度主控本机完成；同步端可上传现有项目 ZIP。

## 连接、名称与界面

- Worker 连接凭证可复制为 `exlab://connect/…`，在 Windows Worker 点击“粘贴连接凭证”。文件方式继续可用。
- 登录 Windows 后启动选项在安装后也可调整；停用状态持久化，登录时不会重新接单。
- Center 和 Worker 支持修改显示名称，中文名称不会改变节点标识、配对 token 或已有实验归属。
- 桌面入口、手机名称、更新来源和新发布资产统一 ExLab。桌面工作空间使用更简洁的导航、统一 SVG 图标、较清晰的层级、响应式卡片与键盘焦点样式。

从 0.4.5 及带有内置更新器的旧版，可以直接在软件中选择“检查更新 → 下载更新 → 安装更新”。`Pencilfinely/experiment-manager` 保留为兼容升级入口，提供旧更新器识别的 `ExperimentManager-0.5.0-…-Setup.exe` 与校验文件；它与 ExLab 安装包内容逐字节相同。安装后软件名称变为 ExLab，后续更新自动使用 `Pencilfinely/exlab`。两端分别更新，原数据目录、Ubuntu 和节点身份继续沿用。

发布维护：运行 `python scripts/build_release.py --legacy-updater`，常规资产发布到 `exlab`，`dist/0.5.0/legacy-updater/` 中的两份安装包与校验文件发布到旧仓库的 `v0.5.0` Release。旧仓库必须真实提供 Releases API 与下载文件；仅依赖 GitHub 改名跳转无法兼容。源码开发使用 `exlab` 地址；旧地址专供软件升级。发布前运行 `scripts/test_legacy_updates.ps1`，发布后加 `-Online`，使用未修改的 0.4.5 更新代码核查发现、下载和校验全过程。

本版保留 Android / HarmonyOS 的应用标识以允许覆盖升级，显示名称与版本号统一为 ExLab Monitor 0.5.0。Android 测试 APK 已完成编译和 Lint，使用原调试签名；原生 HarmonyOS HAP 与两平台真机验收仍需相应构建和设备环境。
