# ExLab 0.5.21 — 恢复接单期间保持 Windows 控制连接

修复 Windows 节点从中控恢复接单时，Docker / WSL 启动阻塞控制心跳，导致节点在恢复途中被判为离线的问题。

- 控制心跳与资源操作分别推进。等待 Docker 启动、停止实验或释放 WSL 时继续回报状态，同一节点仅执行一个资源操作。恢复未完成时不分配实验，失败后仍可回报并重试。
- 安装已有 Worker 时，使用原节点、原服务目录的凭据保存 Windows 控制连接；保持算力原本的停用选择。
- 恢复过程中保留当前进度提示，避免刷新状态将“正在恢复”覆盖为停用。资源操作进行时安装更新继续排队。
- Windows 客户端保留最近 100 条启动与恢复阶段记录，启动失败写入 `last-error.json`，便于核对客户端是否实际接收到中控请求。记录不包含节点凭据。

本次本机部署同时修复了命令行部署环境与桌面客户端读取不同 AppData 副本的问题：安装及客户端启动在正常 Windows 用户会话中执行，并核验真实配置、主控数据库与节点身份。此项属于部署修复。

包含 0.5.20 的 Docker 残留套接字恢复及之前的完整释放、恢复接单和主控性能修复。

提供 Windows Center / Worker 安装器与 ZIP、Ubuntu Worker ZIP、Android Monitor 0.5.21 APK（versionCode 12，沿用原签名）、SHA-256 与构建信息。旧仓库提供相同字节的 Windows 安装器。HarmonyOS 工程同步版本，未提供原生 HAP。
