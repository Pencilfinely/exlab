# ExLab 0.5.24 — 修复 Worker 因 SQLite 写锁竞争退出后持续离线

A6000 的 0.5.22 日志确认：执行循环保存 `compute_control` 时收到 `SQLITE_BUSY / database is locked`，异常逃出管理循环，Worker 退出。SSH 反向隧道仍然监听，但没有代理继续上报心跳。此前的恢复逻辑只处理 `InterfaceError`，没有处理 SQLite 的暂时锁竞争；该日志没有记录当时的具体持锁者。

- 执行循环、实验结果回传和检查点回传保留各自连接，共享短写事务互斥。文件扫描、校验、复制和网络请求继续在写事务外进行。检查点写入使用带提交/回滚的事务，避免失败路径遗留写锁。
- SQLite `BUSY`、`LOCKED` 及其扩展错误码触发管理代理关闭并退避重建，复用原配置、任务记录、attempt 和 generation。Python 3.10 使用明确的锁错误信息识别。损坏、磁盘错误及保存退出期间的错误继续显式失败。
- 初始化遭遇写锁失败时释放部分初始化的连接和代理所有权，再进行重试。退出时等待检查点回传线程结束，防止旧线程存活到下一代代理。
- 回传线程记录错误时若再次遭遇写锁，会回滚并记录脱敏日志，随后重试，不再因二次错误无声退出。

Center 配置与桌面设置：

- 桌面、开始菜单、登录自启及兼容命令行统一沿用保存的数据目录，启动项显式携带原目录。配置写入保留完整备份及独立工作空间绑定；已初始化目录暂时不可用或身份不符时明确失败，避免新建空工作空间。
- Center 网页设置中提供“桌面设置 · 开机自启与自动更新”，托盘增加明确的设置入口。打开设置可操作登录自启和自动更新，不会启用已停用的服务；写入启动项失败时还原开关并显示原因。
- 数据库存在而 `hub.json` 缺失时拒绝重建身份，提示恢复原配置。

保留 0.5.23 的 Center 历史读取、锁公平性和 HTTP 并发优化。Monitor APK 仍为 0.5.22。此修复不会消除电脑关机或 Xshell 隧道断开造成的网络离线。

回归包括真实 SQLite 外部写锁阻塞初始化、内部并发写入、事务回滚、回传错误记录再次遭遇写锁、扩展错误码、损坏和保存退出的失败边界，以及原有 Worker 生命周期、结果回传和更新交接测试。远端安装与新鲜心跳需要在 A6000 上另行验收。
